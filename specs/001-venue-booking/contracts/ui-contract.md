# UI 契約：場地／會議室預約系統

**功能分支**：`001-venue-booking`

## 共用約定

- 路由：hash 路由，`#/login`、`#/change-password` 為登入與改密碼；`#/venues`、`#/venues/:venueId` 為場地搜尋與行事曆；`#/bookings/new`、`#/bookings/:bookingId/edit` 為預約表單；`#/bookings` 為我的預約；`#/waitlist` 為候補；`#/notifications` 為通知；`#/reviews` 為待審核；`#/admin/venues`、`#/admin/users`、`#/admin/bookings`、`#/admin/rules`、`#/admin/reports` 為管理頁。
- 導覽列：登入後每頁顯示導覽列（`[data-testid="app-nav"]`）；桌機寬度（768 像素以上）固定於畫面左側成為側欄，使用者姓名、「變更密碼」與「登出」置於側欄底部；低於 768 像素時改為頂部列。一般員工顯示「場地」「我的預約」「候補」「通知」；具審核者角色或管理員另顯示「待審核」；管理員另顯示「場地管理」「帳號管理」「全部預約」「規則管理」「報表」。右側顯示目前使用者姓名與「變更密碼」（`[data-testid="app-change-password"]`）、「登出」（`[data-testid="app-logout"]`）。「通知」項目旁顯示未讀數徽章（`[data-testid="app-notification-badge"]`），未讀數為 0 時不顯示徽章。寬度低於 768 像素時導覽項目收合，以「選單」按鈕（`[data-testid="app-nav-toggle"]`）展開。選單依角色顯示只是方便，授權以內層為準。
- 路由守衛：未登入開啟任何頁面時導向 `#/login`；登入成功後回到原本要前往的頁面。帳號被標示為須先改密碼時，除 `#/change-password` 與登出外的所有路由一律導向 `#/change-password`。已登入但角色不足的頁面顯示「沒有權限」頁（`[data-testid="app-forbidden"]`），不顯示頁面內容。
- 目前使用者：登入後所有頁面都需要「目前使用者」（識別、姓名、角色、是否須先改密碼、預約權限暫停解除時間）；預約權限被暫停時，我的預約、預約表單與候補頁頂部顯示暫停提示（`[data-testid="suspension-banner"]`），既有預約的報到、取消與修改仍可操作。
- 「現在」的來源：畫面上與「現在」有關的判斷（是否已開始、可否報到、可否取消、今天是幾號、時段是否已過去、候補是否已到期）一律由內層判定並隨資料提供，前端不以裝置時鐘判斷，也不顯示倒數計時，一律顯示絕對時間。
- 時間顯示（NFR-014）：所有時間一律以台北時間（UTC+8）顯示，不隨裝置時區改變；日期格式為「{YYYY}年{M}月{D}日（週{X}）」，時間為 24 小時制 `HH:mm`，起訖寫成 `HH:mm–HH:mm`。表單頁在時間欄位旁提示「時間以台北時間（UTC+8）顯示」。時間輸入用日期欄位加 30 分鐘間隔的下拉選單，只送出台北當地的日期與時分；結束時間下拉選單的最後一項為 `24:00`（表示當日結束）。內層提供的時間點為 UTC，前端一律換算為台北時間顯示，不使用裝置時區；送出的時間輸入不含時區或偏移量（C-SH-02）。
- 訊息語言：繁體中文（`<html lang="zh-Hant-TW">`）。所有失敗訊息說明「發生什麼事」與「可以怎麼做」（NFR-015），不顯示內部錯誤代碼、堆疊或技術細節。預約狀態的中文名稱固定為：待審核、已確認、已報到、已完成、已駁回、已取消、未到場；逾時取消另以「逾時取消」標籤標示。
- 預約狀態代碼（C-SH-01）：預約狀態以英文 snake_case 代碼指稱，與後端、資料庫逐字相同；中文只作顯示文案，對應如下表。畫面依狀態決定行為（顯示哪些按鈕、可否修改、篩選值）時一律依代碼判斷，不依中文文字判斷；狀態標籤的 `data-status` 屬性帶代碼。

  | 代碼         | 顯示文案 |
  | ------------ | -------- |
  | `pending`    | 待審核   |
  | `confirmed`  | 已確認   |
  | `checked_in` | 已報到   |
  | `completed`  | 已完成   |
  | `rejected`   | 已駁回   |
  | `cancelled`  | 已取消   |
  | `no_show`    | 未到場   |

- 定位屬性：以 `data-testid` 標示介面與可操作元素。介面的狀態區塊定位為該介面定位值加上後綴：載入 `-loading`、空狀態 `-empty`、錯誤 `-error`（例如 `my-bookings-loading`）。各操作的元素定位寫在操作欄「操作」名稱後的括號內；列表項目的定位為括號內所列的 `*-item`，單筆項目的識別以 `data-id` 屬性標示。表單欄位的欄位錯誤訊息定位為欄位定位加 `-error`。
- 回饋時限：點擊或送出後 200 毫秒內出現可見回饋（按鈕停用並顯示處理中文字）。可點的控制項在送出前即停用，避免重複送出。
- 版面（NFR-016）：桌機寬度 768 像素以上為多欄版面；低於 768 像素為單欄，表格改為卡片；寬度 360 像素時任何頁面不得需要水平捲動才能操作。
- 無障礙：每個欄位都有可見標籤；錯誤訊息容器使用 `role="alert"`；載入區使用 `aria-busy="true"`；對話框使用 `<dialog>` 並有名稱，開啟後焦點移入、關閉後焦點回到觸發元素，Esc 可關閉；狀態不只靠顏色，一律同時顯示文字；可點目標至少 44 像素高。
- 對話框與疊層不改變 hash。確認對話框的按鈕定位為 `{對話框定位}-confirm` 與 `{對話框定位}-cancel`。
- 輔助區塊定位：`venue-list-region`（UI-02 搜尋結果區）、`calendar-region`（UI-02 行事曆內容區）、`booking-venue-info`（UI-03 場地容納人數與審核說明）、`booking-form-error`（UI-03 表單頂部規則錯誤清單）、`notification-summary`（UI-06 未讀摘要）、`waitlist-notice`（UI-05 操作結果提示區）、`waitlist-register-dialog-error`（UI-05 對話框頂部錯誤）、`venue-hours`／`venue-hours-error`（UI-08 開放時段編輯區與其錯誤）、`venue-reviewers-error`（UI-08 審核者錯誤）、`maintenance-error`（UI-08 維護時段時間錯誤）、`rule-input-error`（UI-11 輸入框錯誤）。
- 提示訊息：操作成功或失敗的頁面提示定位為 `[data-testid="app-toast"]`，失敗提示 `role="alert"`，成功提示 `role="status"`。

## UI-01 登入與密碼介面（登入、變更密碼、首次登入強制改密碼、忘記密碼提示）

**路由**：`#/login`、`#/change-password`
**定位**：`[data-testid="auth-page"]`（登入表單 `[data-testid="auth-login-form"]`，變更密碼表單 `[data-testid="auth-change-form"]`）

### 操作

| 操作                                                                                                | 互動                                                                                                                                                 | 需要內層提供                                                                                                                |
| --------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| 登入（`auth-email`、`auth-password`、`auth-login-submit`）                                          | 輸入 Email 與密碼後送出；Email 前後空白在送出前去除；成功後前往原本要去的頁面，預設為 `#/venues`                                                     | 以 Email 與密碼驗證身分的結果（成功、Email 或密碼錯誤、帳號已停用）；成功時的目前使用者（識別、姓名、角色、是否須先改密碼） |
| 查看忘記密碼提示（`auth-forgot-hint`）                                                              | 登入表單固定顯示提示文字，不提供任何自助重設的連結或按鈕                                                                                             | 無（固定文字）                                                                                                              |
| 首次登入強制改密碼                                                                                  | 登入成功且帳號須先改密碼時，導向 `#/change-password`；頁面顯示說明，且不提供前往其他頁面的導覽，只有「登出」可用                                     | 目前使用者的「是否須先改密碼」                                                                                              |
| 變更密碼（`auth-old-password`、`auth-new-password`、`auth-confirm-password`、`auth-change-submit`） | 輸入舊密碼、新密碼與再次輸入的新密碼後送出；前端先檢查新密碼長度為 8 到 128 個字元、兩次輸入相同；成功後回到登入頁並顯示成功提示，須以新密碼重新登入 | 以舊密碼驗證並設定新密碼的結果（成功、舊密碼不正確、新密碼不符合長度）                                                      |
| 登出（`app-logout`）                                                                                | 點選導覽列的「登出」，結束登入並回到 `#/login`                                                                                                       | 結束目前登入                                                                                                                |

**路由**：`#/venues`（搜尋與列表）、`#/venues/:venueId`（日／週行事曆）
