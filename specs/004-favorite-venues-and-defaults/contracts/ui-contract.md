# UI 契約：我的收藏場地與常用預設值

**功能分支**：`004-favorite-venues-and-defaults`

## 共用約定

- 路由：hash 路由。本功能不新增路由，也不新增收藏清單頁、不提供「只看收藏」篩選。UI-01 在沿用 001 的 `#/venues`（場地搜尋與列表）與 `#/venues/:venueId`（場地日／週行事曆）上增加收藏標記與收藏按鈕；UI-02、UI-03 在沿用 001 的 `#/bookings/new`（單次預約與週期性預約，勾選「重複預約」後為週期性）、`#/bookings/:bookingId/edit`（修改預約），以及 002 的 `#/bookings/new?from={預約識別}`（再預約一次）上調整場地選單與欄位預填；登記候補對話框為疊層，可從 `#/venues/:venueId` 與 `#/bookings/new` 開啟（沿用 001 UI-05），不改變 hash，其場地選單同受 UI-02 約束。其餘路由（`#/login`、`#/bookings`、`#/waitlist` 等）沿用 001、002、003，不在本契約範圍。
- 本功能的範圍：只增加「場地收藏」與「單次預約表單預填上次的人數與時長」。預約規則、預約送出流程、被拒絕時的規則清單、替代建議（003）、再預約一次（002）的行為一律沿用，本功能不複製、不修改任何預約規則。
- 導覽列：登入後每頁顯示導覽列（`[data-testid="app-nav"]`）；桌機寬度（768 像素以上）固定於畫面左側成為側欄，低於 768 像素時改為頂部列並以「選單」按鈕（`[data-testid="app-nav-toggle"]`）展開。場地頁的導覽高亮項目為「場地」，預約表單相關頁面的導覽高亮項目為「我的預約」。導覽項目依角色顯示只是方便，授權以內層為準。
- 路由守衛：未登入開啟任何頁面時導向 `#/login`，登入成功後回到原本要前往的頁面；帳號被標示為須先改密碼時，除 `#/change-password` 與登出外的所有路由一律導向 `#/change-password`。
- 目前使用者：三個介面都需要「目前使用者」（識別、姓名、角色、預約權限暫停解除時間）。預約權限暫停期間，預約表單頂部顯示暫停提示（`[data-testid="suspension-banner"]`）；暫停不影響收藏操作。
- 「現在」的來源：與「現在」有關的判斷（時段是否已過去、可預約的最遠日、今天是幾號）一律由內層判定，前端不以裝置時鐘判斷。
- 個人資料界線（NFR-002）：收藏與記住的預設值只屬於目前使用者本人。前端只顯示內層回傳給目前使用者的收藏與預設值，不顯示、不推測他人的收藏或預設值；前端不以瀏覽器儲存空間（localStorage、cookie 等）保存收藏或預設值，換裝置或重新登入後以內層為準（邊界情況：不同裝置一致）。
- 儲存失敗不影響預約（NFR-001）：收藏或預設值載入失敗時，預約表單仍可照 001 的方式填寫與送出，只在對應位置顯示提示，不阻擋送出。
- 時間顯示（C-SH-02、NFR-003）：畫面上的時間一律以台北時間（UTC+8）顯示、不隨裝置時區改變，且時間輸入只送出台北當地的日期與時分，不含時區或偏移量。內層提供的時間點為帶 `Z` 的 ISO 8601 UTC 字串，前端換算為台北時間後顯示，不使用裝置時區。日期格式為「{YYYY}年{M}月{D}日（週{X}）」，時間為 24 小時制 `HH:mm`，起訖寫成 `HH:mm–HH:mm`；結束時間正好是台北當天結束時寫成 `24:00`。預約表單在時間欄位旁提示「時間以台北時間（UTC+8）顯示」。時間輸入用日期欄位加 30 分鐘間隔的下拉選單；結束時間下拉選單的最後一項為 `24:00`（表示當日結束）。依記住的時長帶出結束時間時，以台北當地的時分計算，不使用裝置時區。
- 預約狀態代碼（C-SH-01）：預約狀態以英文 snake_case 代碼指稱，與後端、資料庫逐字相同；中文只作顯示文案，對應如下表。畫面依狀態決定行為時一律依代碼判斷，不依中文文字判斷；狀態標籤的 `data-status` 屬性帶代碼；畫面上只顯示中文文案，不顯示代碼。本功能的收藏與預設值與預約狀態代碼無關：只有「單次預約成立」這個結果（狀態 `confirmed` 或 `pending`）會讓內層更新預設值，前端不依狀態代碼決定任何預設值行為。

  | 代碼         | 顯示文案 |
  | ------------ | -------- |
  | `pending`    | 待審核   |
  | `confirmed`  | 已確認   |
  | `checked_in` | 已報到   |
  | `completed`  | 已完成   |
  | `rejected`   | 已駁回   |
  | `cancelled`  | 已取消   |
  | `no_show`    | 未到場   |

- 訊息語言：繁體中文（`<html lang="zh-Hant-TW">`）。所有失敗訊息說明「發生什麼事」與「可以怎麼做」，不顯示內部規則代碼、錯誤代碼、堆疊或技術細節。
- 定位屬性：以 `data-testid` 標示介面與可操作元素。介面的狀態區塊定位為該介面定位值加上後綴：載入 `-loading`、空狀態 `-empty`、錯誤 `-error`。各操作的元素定位寫在操作欄「操作」名稱後的括號內；列表項目的識別以 `data-id` 屬性標示（場地識別）。表單欄位的欄位錯誤訊息定位為欄位定位加 `-error`，欄位的輔助說明定位為欄位定位加 `-hint`。本功能新增的定位為各介面「操作」欄括號內所列；沿用 001、002 的定位不變，原型中出現者包含：場地頁的 `venue-search`、`venue-list-region`、`venue-list`、`venue-list-item`、`venue-open-calendar`、`venue-filter-*`、`venue-calendar`、`calendar-*`、`venue-search-loading`、`venue-search-empty`、`venue-search-error`、`venue-calendar-loading`、`venue-calendar-empty`、`venue-calendar-error`；預約表單的 `booking-form`、`booking-date`、`booking-start`、`booking-end`、`booking-subject`、`booking-attendees`、`booking-venue-info`、`booking-recurring-toggle`、`booking-recurrence-frequency`、`booking-recurrence-end`、`booking-submit`、`booking-back`、`booking-result`、`booking-go-my-bookings`、`booking-form-error`、`booking-waitlist-link`、`booking-rebook-notice`、`booking-rebook-general-link`、`suspension-banner`；登記候補對話框的 `waitlist-register-*`；導覽與提示的 `app-nav`、`app-nav-toggle`、`app-nav-venues`、`app-nav-bookings`、`app-change-password`、`app-logout`、`app-forbidden`、`app-toast`。各欄位的欄位錯誤訊息為欄位定位加 `-error`（例如 `booking-venue-error`）。
- 回饋時限：點擊或送出後 200 毫秒內出現可見回饋（按鈕停用並顯示處理中文字）。可點的控制項在送出前即停用，避免重複送出。
- 版面（NFR-003）：桌機寬度 768 像素以上為多欄版面；低於 768 像素為單欄，卡片與按鈕換行排列；寬度 360 像素時，收藏按鈕、收藏標記、「我的收藏」分組選單與預填說明文字都不得需要水平捲動才能操作。
- 無障礙：每個欄位都有可見標籤；錯誤訊息容器使用 `role="alert"`；載入區使用 `aria-busy="true"`；狀態不只靠顏色，收藏標記一律同時顯示文字「已收藏」；收藏按鈕為實際的 `<button type="button">` 並以 `aria-pressed` 表示是否已收藏；可點目標至少 44 像素高。
- 提示訊息：操作成功或失敗的頁面提示定位為 `[data-testid="app-toast"]`，失敗提示 `role="alert"`，成功提示 `role="status"`。

## UI-01 場地收藏操作介面（查詢結果與行事曆上的收藏標記、加入與取消收藏、結果提示、停用場地的拒絕提示、重複點擊）

**路由**：`#/venues`（查詢結果的場地卡）、`#/venues/:venueId`（行事曆頁頭）
**定位**：`[data-testid="venue-search"]` 內的 `[data-testid="venue-favorite-toggle"]`（查詢結果）、`[data-testid="venue-calendar"]` 內的 `[data-testid="calendar-favorite-toggle"]`（行事曆）

### 操作

| 操作 | 互動 | 需要內層提供 |
| ---- | ---- | ------------ |
| 看見收藏標記（`venue-favorite-mark`） | 場地卡（`venue-list-item`）與行事曆頁頭上，目前使用者已收藏的場地顯示標記「已收藏」（星形圖示加文字）；未收藏的場地不顯示標記。標記只表示本人的收藏，不影響場地列表的順序與篩選結果，也不新增「只看收藏」篩選 | 場地列表與行事曆場地資訊中，每個場地附「本人是否已收藏」；只含本人的收藏 |
| 加入收藏（`venue-favorite-toggle`、`calendar-favorite-toggle`） | 未收藏的啟用中場地顯示「加入收藏」按鈕（`aria-pressed="false"`），只需 1 次點擊。按下後 200 毫秒內按鈕停用並顯示「處理中…」；成功後標記變為「已收藏」、按鈕變為「取消收藏」（`aria-pressed="true"`），頁面提示顯示「已加入收藏」，焦點留在該按鈕。處理中按鈕停用，再按無效；若兩次點擊都已送出，以內層的結果為準，最終仍為已收藏。查詢結果與行事曆上的效果相同 | 加入收藏（場地識別）的結果：成功並回傳目前的收藏狀態（重複加入視為成功、不產生第二筆）；或失敗原因（場地已停用、其他失敗）。只能為本人加入 |
| 取消收藏（`venue-favorite-toggle`、`calendar-favorite-toggle`） | 已收藏的場地顯示「取消收藏」按鈕。按下後 200 毫秒內按鈕停用並顯示「處理中…」；成功後標記消失、按鈕變回「加入收藏」，頁面提示顯示「已取消收藏」，焦點留在該按鈕。取消不需確認對話框 | 取消收藏（場地識別）的結果：成功並回傳目前的收藏狀態（重複取消視為成功、不報錯）；或失敗原因。只能取消本人的收藏 |
| 場地已停用時加入收藏被拒絕（`venue-favorite-disabled-tag`） | 頁面開著期間場地被停用，按「加入收藏」被內層拒絕時，收藏狀態不變，頁面提示（失敗）顯示「此場地已停用，無法收藏」；該場地卡或行事曆頁頭加上標籤「已停用」，「加入收藏」按鈕改為停用，因為頁面資料已過期。已收藏的場地仍可按「取消收藏」。重新載入頁面後，停用的場地依 001 不再出現在查詢結果 | 同「加入收藏」的失敗原因（場地已停用）；已停用場地的取消收藏仍可成功 |
| 收藏操作失敗（`app-toast`） | 加入或取消因網路或其他原因失敗時，收藏狀態與標記維持操作前的樣子，頁面提示（失敗）顯示原因與可做的事，按鈕恢復可用，可再按一次 | 同「加入收藏」「取消收藏」的失敗原因 |

### 狀態

| 狀態 | 呈現 |
| ---- | ---- |
| 成功 | 場地卡與行事曆頁頭依本人的收藏顯示標記與對應的按鈕（未收藏為「加入收藏」，已收藏為「取消收藏」並帶「已收藏」標記）；操作成功後立即更新該場地的標記與按鈕，並顯示結果提示 |
| 載入 | 場地列表與行事曆的載入沿用 001（骨架佔位）；載入期間收藏按鈕不顯示。單次收藏操作送出後，該按鈕顯示「處理中…」並停用，`aria-busy="true"`，其他場地的按鈕仍可操作 |
| 空狀態 | 不單獨出現；沒有任何場地時沿用 001 的「目前沒有可預約的場地」，沒有任何場地就沒有收藏按鈕。員工尚未收藏任何場地不是空狀態：所有場地都顯示「加入收藏」，不顯示「我的收藏」相關的空白區塊或提示 |
| 錯誤 | 場地列表或行事曆載入失敗沿用 001（錯誤訊息與「重新載入」）。收藏操作失敗：標記與按鈕維持操作前，頁面提示顯示失敗原因；場地已停用：顯示「此場地已停用，無法收藏」並標示「已停用」；收藏狀態在任何失敗下都不改變 |

## UI-02 預約表單場地選單介面（我的收藏區、空收藏時不顯示、不自動選定場地、停用場地不顯示、修改預約維持原場地）

**路由**：`#/bookings/new`（單次預約與週期性預約）、`#/bookings/:bookingId/edit`（修改預約）；登記候補對話框從 `#/venues/:venueId` 與 `#/bookings/new` 開啟，不改變 hash。再預約（`#/bookings/new?from={預約識別}`）的場地固定唯讀，不使用場地選單，不屬於本介面
**定位**：`[data-testid="booking-form"]` 內的 `[data-testid="booking-venue"]`、登記候補對話框內的 `[data-testid="waitlist-register-venue"]`

### 操作

| 操作 | 互動 | 需要內層提供 |
| ---- | ---- | ------------ |
| 開啟場地選單並選場地（`booking-venue`、`booking-venue-group-favorites`、`booking-venue-group-others`） | 本人有可顯示的收藏場地時，場地選單分兩組：先「我的收藏」（`booking-venue-group-favorites`），列出本人收藏且啟用中的場地，依場地名稱排序；其後「其他場地」（`booking-venue-group-others`），列出其餘啟用中的場地，順序沿用 001。每個場地只出現一次，收藏的場地不在「其他場地」重複出現。選項文字為「{場地名稱}（{地點}）」。選定場地後沿用 001 顯示場地資訊（`booking-venue-info`） | 啟用中場地列表（識別、名稱、地點、容納人數、是否需審核、設備），每個附「本人是否已收藏」；已停用場地不在列表內，其收藏紀錄由內層保留，場地重新啟用後自動回到列表並仍標示已收藏 |
| 沒有收藏時維持原樣（`booking-venue`） | 本人沒有任何可顯示的收藏場地（從未收藏、全部取消，或收藏的場地都已停用）時，場地選單不分組，不顯示空的「我的收藏」區，也不顯示「其他場地」的組別名稱，呈現與 001 相同的單一清單 | 同上（沒有任何「已收藏」的啟用中場地） |
| 不自動選定場地（`booking-venue`） | 新增預約、週期性預約與登記候補對話框開啟時，場地欄位停在佔位選項「請選擇場地」，不因為有收藏場地而選定任何場地；由行事曆「預約此時段」或候補入口帶入場地時，依帶入的場地選定（沿用 001）。未選場地就送出時，欄位下方顯示「請選擇場地。」並不送出 | 無（帶入的場地識別由網址或呼叫端提供，沿用 001） |
| 修改預約維持原場地（`booking-venue`） | 修改預約開啟時，場地欄位顯示該預約目前的場地；展開選單時同樣先「我的收藏」再「其他場地」，目前場地若為收藏則出現在「我的收藏」區。不因收藏改變目前顯示的場地 | 既有預約的場地識別（沿用 001）；其餘同上 |
| 週期性預約與登記候補使用同樣的分組（`booking-recurring-toggle`、`waitlist-register-venue`） | 在預約表單勾選「重複預約」後，場地選單分組方式不變；登記候補對話框的場地選單（`waitlist-register-venue`）同樣先「我的收藏」再「其他場地」，對話框開啟時若呼叫端沒有帶入場地則停在「請選擇場地」 | 同上 |
| 再預約表單不使用場地選單（`booking-venue`） | 再預約模式的場地固定唯讀（沿用 002），不顯示選單、不分組；想換場地仍用 002 的「改為一般預約」連結，回到一般預約表單後依上列行為分組 | 無（是否為再預約模式由網址是否帶 `from` 判定，前端自行判斷） |
| 收藏載入失敗時的降級（`booking-favorites-error`） | 取不到本人的收藏時，場地選單退回不分組的單一清單（與 001 相同），表單頂部顯示提示，仍可正常選場地與送出 | 無（內層未回傳收藏） |

### 狀態

## UI-03 預約表單預填介面（人數預填、依時長帶出結束時間、手動修改、套不上時不帶出、再預約與修改與週期性不使用）

**路由**：`#/bookings/new`（單次預約，勾選「重複預約」即為週期性預約）；`#/bookings/:bookingId/edit` 與 `#/bookings/new?from={預約識別}` 不使用預填，列於本介面是為了定義不預填的行為
**定位**：`[data-testid="booking-form"]` 內的 `[data-testid="booking-attendees"]` 與 `[data-testid="booking-end"]`

### 操作

| 操作 | 互動 | 需要內層提供 |
| ---- | ---- | ------------ |
| 一般開啟單次預約表單時預填人數（`booking-attendees`、`booking-attendees-hint`） | 未帶 `from`、非修改模式、未勾選「重複預約」，且本人有記住的人數時，人數欄位已填入上次成功預約的人數，欄位下方說明「已帶入上次預約的人數，可自行修改。」。日期、場地、主題與開始時間不預填，維持空白待選（有預約紀錄時，開始時間停在「請選擇」；從未預約時不套用本列，起訖時間沿用 001 的初始值 09:00、09:30）。員工可在送出前修改人數，修改後說明消失。預填不隨所選場地改變；預填人數超過所選場地容納人數時，沿用 001：失焦時欄位下方提示、不攔截送出，送出後由內層拒絕並顯示原因 | 目前使用者記住的預設值：人數與時長（每位員工一份，取自最近一次成功建立的單次預約）；從未成功預約時為空值 |
| 選定開始時間後依時長帶出結束時間（`booking-start`、`booking-end`、`booking-end-hint`） | 單次預約表單、員工尚未手動改過結束時間，且有記住的時長時，每次選定或更改開始時間，結束時間自動帶出為「開始時間加時長」，欄位下方說明「已依上次的時長 {時長} 帶出，可自行修改。」。結束時間下拉選單的選項不變（30 分鐘間隔，最後一項 `24:00`）。網址已帶入開始與結束時間（例如行事曆「預約此時段」）時，以帶入的值為準，不套用記住的時長 | 同上（記住的時長）；單次時長上限規則值；所選場地在所選日期的開放時段（台北當地起訖時分，不開放則為無），供前端判斷帶出的結束時間是否落在開放時段內。最終是否可預約仍由內層在送出時判定 |
| 手動修改結束時間（`booking-end`） | 員工自己改了結束時間後，以手動值為準：之後再改開始時間、場地或日期，都不再自動帶出或清掉結束時間，由既有的欄位檢查處理（結束須晚於開始）。員工把結束時間改回「請選擇」也視為手動 | 無 |
| 套不上時不帶出結束時間（`booking-end-hint`） | 記住的時長超過現行單次時長上限，或帶出的結束時間超出所選場地在所選日期的開放時段，或超過當天 `24:00`（不在同一天）時，結束時間不自動帶出，維持「請選擇」，欄位下方說明「上次的時長（{時長}）套用後超出可預約範圍，請自行選擇結束時間。」。記住的時長超過上限時，開啟表單當下就顯示這項說明（不必先選開始時間），人數仍照常預填。開始時間、場地或日期之後改變使結果變為可套用或不可套用時，只要員工尚未手動改過結束時間，就隨之重新帶出或清除 | 同上 |
| 勾選或取消「重複預約」（`booking-recurring-toggle`） | 勾選「重複預約」（週期性預約）時，不使用記住的值：尚未被員工手動輸入的預填人數清空回空白，自動帶出的結束時間清空回「請選擇」，相關說明消失，且不再自動帶出；員工已手動輸入或改過的值保留。取消勾選回到單次預約時，尚未被員工手動改過的欄位重新預填人數，並依已選的開始時間重新帶出結束時間 | 無（沿用同一份預設值，不另取） |
| 修改預約與再預約不使用預填（`booking-attendees`、`booking-end`） | 修改預約：人數與起訖維持該預約原值。再預約一次：人數為 002 帶入的來源預約人數，不使用記住的人數；結束時間依 002 不預填、不依記住的時長帶出。兩者都不顯示預填說明 | 既有預約或來源預約的人數與起訖（沿用 001、002） |
| 預設值載入失敗時的降級（`booking-defaults-error`） | 取不到記住的預設值時，視同從未預約：人數維持空白，起訖時間維持 001 的初始值（開始 09:00、結束 09:30），表單頂部顯示提示，仍可正常填寫與送出 | 無（內層未回傳預設值） |
| 送出後預設值的更新 | 單次預約（含由「再預約一次」建立）成立後，內層以該筆預約的人數與時長取代預設值；預約被拒絕、員工放棄表單、修改預約、取消預約、建立週期性預約與確認候補遞補都不更新。前端不自行保存或更新預設值，下次開啟表單時以內層回傳為準 | 單次預約建立結果（沿用 001／003：成立並回傳狀態 `confirmed` 或 `pending`，或未通過的規則清單）；預設值的更新由內層在建立成功時完成，不需前端另送 |

### 狀態

| 狀態 | 呈現 |
| ---- | ---- |
| 成功 | 人數已預填並附說明，選定開始時間後結束時間自動帶出並附說明；日期、場地、主題與起訖時間維持空白待選。員工可自由修改人數與結束時間 |

| 錯誤 | 預設值載入失敗：視同空狀態，表單頂部顯示「無法載入上次的人數與時長，請自行填寫。」（`booking-defaults-error`），不阻擋送出。時長套不上：結束時間維持「請選擇」並顯示套不上的說明。預填的人數超過容納人數或結束時間造成違規：沿用 001／003 的規則清單，依規則顯示未通過的原因 |
