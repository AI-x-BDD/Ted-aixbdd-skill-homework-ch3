# UI 契約：一鍵「再預約一次」

**功能分支**：`002-rebook-reservation`

## 共用約定

- 路由：hash 路由。`#/bookings` 為我的預約（UI-01，沿用 001 的路由，在每筆預約旁加按鈕）；`#/bookings/new?from={預約識別}` 為再預約預填表單（UI-02，由 001 的 `#/bookings/new` 擴充 `from` 參數）。未帶 `from` 時 `#/bookings/new` 維持 001 的一般預約表單行為。其餘路由（`#/login`、`#/venues`、`#/waitlist` 等）沿用 001，不在本契約範圍。
- 導覽列：登入後每頁顯示導覽列（`[data-testid="app-nav"]`）；桌機寬度（768 像素以上）固定於畫面左側成為側欄，低於 768 像素時改為頂部列並以「選單」按鈕（`[data-testid="app-nav-toggle"]`）展開。再預約相關頁面的導覽高亮項目為「我的預約」。導覽項目依角色顯示只是方便，授權以內層為準。
- 路由守衛：未登入開啟任何頁面時導向 `#/login`，登入成功後回到原本要前往的頁面；帳號被標示為須先改密碼時，除 `#/change-password` 與登出外的所有路由一律導向 `#/change-password`。
- 目前使用者：兩個介面都需要「目前使用者」（識別、姓名、角色、預約權限暫停解除時間）。預約權限暫停期間，我的預約與預約表單頂部顯示暫停提示（`[data-testid="suspension-banner"]`），既有預約的報到、取消與修改仍可操作。
- 「現在」的來源：與「現在」有關的判斷（是否已開始、時段是否已過去、可預約的最遠日、今天是幾號）一律由內層判定並隨資料提供，前端不以裝置時鐘判斷。
- 時間顯示（C-SH-02、NFR-003）：畫面上的時間一律以台北時間（UTC+8）顯示、不隨裝置時區改變，且時間輸入只送出台北當地的日期與時分，不含時區或偏移量。內層提供的時間點為帶 `Z` 的 ISO 8601 UTC 字串，前端換算為台北時間後顯示，不使用裝置時區。日期格式為「{YYYY}年{M}月{D}日（週{X}）」，時間為 24 小時制 `HH:mm`，起訖寫成 `HH:mm–HH:mm`。僅有一處例外：按鈕旁的暫停解除日期依規格 spec.md 驗收情境 7 的寫法，以台北日期 `YYYY-MM-DD` 顯示（例如 2026-11-12）。表單頁在時間欄位旁提示「時間以台北時間（UTC+8）顯示」。時間輸入用日期欄位加 30 分鐘間隔的下拉選單；結束時間下拉選單的最後一項為 `24:00`（表示當日結束）。
- 預約狀態代碼（C-SH-01）：預約狀態以英文 snake_case 代碼指稱，與後端、資料庫逐字相同；中文只作顯示文案，對應如下表。畫面依狀態決定行為時一律依代碼判斷，不依中文文字判斷；狀態標籤的 `data-status` 屬性帶代碼。本功能的「再預約一次」按鈕對下列七個代碼一視同仁，是否可按與狀態代碼無關，只取決於場地啟用狀態與預約權限是否暫停。

  | 代碼         | 顯示文案 |
  | ------------ | -------- |
  | `pending`    | 待審核   |
  | `confirmed`  | 已確認   |
  | `checked_in` | 已報到   |
  | `completed`  | 已完成   |
  | `rejected`   | 已駁回   |
  | `cancelled`  | 已取消   |
  | `no_show`    | 未到場   |

- 訊息語言：繁體中文（`<html lang="zh-Hant-TW">`）。所有失敗訊息說明「發生什麼事」與「可以怎麼做」，不顯示內部錯誤代碼、堆疊或技術細節（NFR-003）。
- 定位屬性：以 `data-testid` 標示介面與可操作元素。介面的狀態區塊定位為該介面定位值加上後綴：載入 `-loading`、空狀態 `-empty`、錯誤 `-error`。各操作的元素定位寫在操作欄「操作」名稱後的括號內；列表項目的識別以 `data-id` 屬性標示。表單欄位的欄位錯誤訊息定位為欄位定位加 `-error`。
- 回饋時限：點擊或送出後 200 毫秒內出現可見回饋（按鈕停用並顯示處理中文字）。可點的控制項在送出前即停用，避免重複送出（NFR-001）。
- 版面（NFR-004）：桌機寬度 768 像素以上為多欄版面；低於 768 像素為單欄，表格改為卡片；寬度 360 像素時任何頁面不得需要水平捲動才能操作。按鈕與其原因文字在窄螢幕下上下排列，不橫向溢出。
- 無障礙：每個欄位都有可見標籤；錯誤訊息容器使用 `role="alert"`；載入區使用 `aria-busy="true"`；停用的按鈕以 `aria-describedby` 連到同列的可見原因文字，不使用只有懸停才出現的提示；狀態不只靠顏色，一律同時顯示文字；可點目標至少 44 像素高。
- 提示訊息：操作成功或失敗的頁面提示定位為 `[data-testid="app-toast"]`，失敗提示 `role="alert"`，成功提示 `role="status"`。

## UI-01 我的預約的再預約按鈕介面（按鈕、停用狀態與原因文案）

**路由**：`#/bookings`
**定位**：`[data-testid="my-bookings"]`（沿用 001 的我的預約；本功能新增的按鈕為 `booking-rebook-button`）

### 操作

| 操作                                                                       | 互動                                                                                                                                                                                                                                                                                                                                                                  | 需要內層提供                                                                                                                                                                        |
| -------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 顯示再預約按鈕（`booking-rebook-button`、`booking-rebook-reason`）         | 「即將到來」與「已結束」兩個分頁（沿用 001 的 `my-bookings-tab-upcoming`、`my-bookings-tab-past`、`my-bookings-list`）的每筆預約（`my-bookings-item`）動作列都顯示「再預約一次」，不論狀態代碼為 `pending`、`confirmed`、`checked_in`、`completed`、`rejected`、`cancelled` 或 `no_show`，週期性預約的場次也一樣。可按時按鈕為一般按鈕；不可按時按鈕 `disabled`，並在同一列以可見文字顯示原因（`booking-rebook-reason`）                                      | 每筆預約的所屬場地是否啟用（啟用／已停用）；目前使用者的預約權限暫停解除時間（未暫停時為空）                                                                                        |
| 判定按鈕可否按                                                             | 依序判斷：預約權限暫停中，所有預約的按鈕都不可按，原因為「預約權限暫停中，{解除日期} 解除」；否則所屬場地已停用，該筆的按鈕不可按，原因為「此場地已停用，無法再預約」；兩者同時成立時只顯示暫停原因；皆不成立時可按且不顯示原因。判斷只用頁面載入時取得的資料，不以裝置時鐘判斷，也不為此多送請求。該時段維護中等其他場地問題不在按鈕判斷，留待送出時由內層規則檢查 | 同上（不另外需要資料）                                                                                                                                                              |
| 開啟再預約表單（`booking-rebook-button`）                                  | 按下可按的按鈕，前往 `#/bookings/new?from={預約識別}`（UI-02）；不建立任何預約，來源預約不受影響                                                                                                                                                                                                                                                                      | 無（預約識別已在列表資料中）                                                                                                                                                        |
| 看見再預約成功提示（`app-toast`）                                          | 由 UI-02 送出成功後導回本頁，頁面頂部顯示含新預約狀態的成功提示（`role="status"`），並顯示在「即將到來」分頁；新預約出現在清單中，來源預約的狀態、時間、主題與人數維持原樣                                                                                                                                                                                              | 重新取得的我的預約列表（含新建立的預約，狀態代碼為 `confirmed` 或 `pending`）；來源預約資料不得因再預約而改變                                                                       |

### 狀態

| 狀態   | 呈現                                                                                                                                                                                                                                                                                                |
| ------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 成功   | 每筆預約動作列顯示「再預約一次」。可按：一般樣式。不可按（場地已停用或權限暫停中）：停用樣式，按鈕下方（桌機為按鈕右側）以一般字級的可見文字顯示原因，不靠懸停。權限暫停中時頁面頂部另有暫停提示，且全部按鈕停用。再預約成功導回時頂部顯示成功提示                                                      |
| 載入   | 沿用 001：列表位置顯示骨架卡片，清單載入完成前不顯示任何再預約按鈕，版面不跳動，容器 `aria-busy="true"`。按下按鈕後瀏覽器切換至 UI-02，不在本頁停留                                                                                                                                                  |
| 空狀態 | 沿用 001：沒有預約時顯示空狀態引導，沒有任何再預約按鈕；「即將到來」沒有預約但「已結束」有時，已結束分頁照常顯示按鈕                                                                                                                                                                                |
| 錯誤   | 清單載入失敗時顯示錯誤訊息與「重新載入」，不顯示再預約按鈕。按鈕可按但頁面載入後場地才被停用、或暫停才開始時，按鈕仍可按，進入 UI-02 送出後由內層規則拒絕並顯示原因，不會建立預約                                                                                                                  |

## UI-02 再預約預填表單介面（預填場地／主題／人數、場地唯讀、必填提示、規則拒絕訊息、成功提示、放棄離開）

**路由**：`#/bookings/new?from={預約識別}`
**定位**：`[data-testid="booking-form"]`（沿用 001 的預約表單定位；`from` 存在時為再預約模式）

### 操作

| 操作                                                                                                        | 互動                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | 需要內層提供                                                                                                                                                                                                                                                                                                      |
| ----------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

### 狀態

| 狀態   | 呈現                                                                                                                                                                                                                                                                                                                                                                                       |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 成功   | 頂部有預填說明；場地唯讀並顯示容納人數與審核說明；主題與人數已帶入且可改；日期與開始、結束時間為空待選；送出成功不停留本頁，導回 UI-01 並顯示成功提示                                                                                                                                                                                                                                       |
| 載入   | 載入來源預約與場地資訊時，欄位位置顯示骨架，容器 `aria-busy="true"`；送出時按鈕顯示「送出中…」並停用，欄位停用，表單 `aria-busy="true"`                                                                                                                                                                                                                                                       |
| 空狀態 | 不以空清單的形式單獨出現。日期與起訖時間初始為空即預設畫面；未選就按送出時，不送出，並在日期、開始時間、結束時間欄位下方顯示必填提示，焦點移到第一個有錯誤的欄位                                                                                                                                                                                                                              |
| 錯誤   | 欄位錯誤顯示在欄位下方並標示欄位；內層回傳的未通過規則以清單顯示在表單頂部，時段被占用時附「登記候補」，預約權限暫停時顯示暫停解除時間，表單內容保留。來源預約不存在或非本人：顯示「找不到這筆預約，無法帶入內容」與「改為一般預約」連結，不顯示預填內容。載入失敗：顯示錯誤訊息與「重新載入」。來源場地已停用：表單停用並說明原因。權限暫停中：頂部顯示暫停提示，送出仍可嘗試並由內層拒絕 |
