# UI 契約：預約衝突時推薦替代時段／場地

**功能分支**：`003-conflict-alternatives`

## 共用約定

- 路由：hash 路由。本功能不新增路由，兩個介面都在既有的預約表單內：`#/bookings/new`（一般預約，沿用 001）、`#/bookings/:bookingId/edit`（修改既有預約，沿用 001）、`#/bookings/new?from={預約識別}`（再預約一次，沿用 002）。其餘路由（`#/login`、`#/venues`、`#/bookings`、`#/waitlist` 等）沿用 001、002，不在本契約範圍。
- 本功能的範圍：只在「單次預約的建立、修改預約、再預約一次」被拒絕的結果區塊增加替代建議。週期性預約（勾選「重複預約」）的衝突日期清單、登記候補流程與管理員操作維持現狀，不顯示替代建議；本功能不新增、不改變、也不保存任何預約。
- 導覽列：登入後每頁顯示導覽列（`[data-testid="app-nav"]`）；桌機寬度（768 像素以上）固定於畫面左側成為側欄，低於 768 像素時改為頂部列並以「選單」按鈕（`[data-testid="app-nav-toggle"]`）展開。預約表單相關頁面的導覽高亮項目為「我的預約」。導覽項目依角色顯示只是方便，授權以內層為準。
- 路由守衛：未登入開啟任何頁面時導向 `#/login`，登入成功後回到原本要前往的頁面；帳號被標示為須先改密碼時，除 `#/change-password` 與登出外的所有路由一律導向 `#/change-password`。
- 目前使用者：預約表單需要「目前使用者」（識別、姓名、角色、預約權限暫停解除時間）。預約權限暫停期間，表單頂部顯示暫停提示（`[data-testid="suspension-banner"]`）；暫停期間送出時，暫停也算一項未通過的規則，與其他規則並列，不顯示替代建議。
- 「現在」的來源：與「現在」有關的判斷（時段是否已過去、可預約的最遠日、今天是幾號）一律由內層判定，前端不以裝置時鐘判斷；替代建議由內層依最新狀況計算，前端不自行計算空檔、不自行篩選場地，也不複製任何預約規則。
- 時間顯示（C-SH-02、NFR-004）：畫面上的時間一律以台北時間（UTC+8）顯示、不隨裝置時區改變，且時間輸入只送出台北當地的日期與時分，不含時區或偏移量。內層提供的時間點（包含替代建議的起訖）為帶 `Z` 的 ISO 8601 UTC 字串，前端換算為台北時間後顯示，也以換算後的台北當地日期與時分填回表單，不使用裝置時區。日期格式為「{YYYY}年{M}月{D}日（週{X}）」，時間為 24 小時制 `HH:mm`，起訖寫成 `HH:mm–HH:mm`；結束時間正好是台北當天結束時寫成 `24:00`。表單頁在時間欄位旁提示「時間以台北時間（UTC+8）顯示」。時間輸入用日期欄位加 30 分鐘間隔的下拉選單；結束時間下拉選單的最後一項為 `24:00`（表示當日結束）。
- 預約狀態代碼（C-SH-01）：預約狀態以英文 snake_case 代碼指稱，與後端、資料庫逐字相同；中文只作顯示文案，對應如下表。畫面依狀態決定行為時一律依代碼判斷，不依中文文字判斷；狀態標籤的 `data-status` 屬性帶代碼；畫面上只顯示中文文案，不顯示代碼。本功能中預約成立後的狀態由所選場地是否需審核決定：不需審核為 `confirmed`，需審核為 `pending`；「需審核」標示是場地的屬性，不是預約狀態代碼。

  | 代碼         | 顯示文案 |
  | ------------ | -------- |
  | `pending`    | 待審核   |
  | `confirmed`  | 已確認   |
  | `checked_in` | 已報到   |
  | `completed`  | 已完成   |
  | `rejected`   | 已駁回   |
  | `cancelled`  | 已取消   |
  | `no_show`    | 未到場   |

- 訊息語言：繁體中文（`<html lang="zh-Hant-TW">`）。所有失敗訊息說明「發生什麼事」與「可以怎麼做」，不顯示內部規則代碼、錯誤代碼、堆疊或技術細節（NFR-004）。
- 隱私（NFR-003）：撞期訊息與替代建議不顯示占用該時段者是誰，也不顯示其預約主題或人數；前端也不向內層索取這些資料。
- 定位屬性：以 `data-testid` 標示介面與可操作元素。介面的狀態區塊定位為該介面定位值加上後綴：空狀態 `-empty`。本功能的建議與撞期訊息同一次到達，沒有獨立的載入區塊與錯誤區塊：載入呈現為表單忙碌，錯誤呈現在沿用的 `booking-form-error`（各介面的「狀態」表說明）。各操作的元素定位寫在操作欄「操作」名稱後的括號內；列表項目的識別以 `data-id` 屬性標示。表單欄位的欄位錯誤訊息定位為欄位定位加 `-error`。建議區塊的外層容器為 `[data-testid="alt-suggestions"]`，其中包含 UI-01 與 UI-02 的區塊；點選建議後的提示為 `[data-testid="alt-applied-notice"]`。
- 回饋時限：點擊或送出後 200 毫秒內出現可見回饋（按鈕停用並顯示處理中文字）。可點的控制項在送出前即停用，避免重複送出。撞期被拒絕時，含建議的完整結果在 2 秒內顯示（NFR-001，由內層負責）。
- 版面（NFR-005）：桌機寬度 768 像素以上為多欄版面；低於 768 像素為單欄；寬度 360 像素時，建議區塊與按鈕換行排列，任何頁面不得需要水平捲動才能操作。建議按鈕在窄螢幕下上下換行，不橫向溢出。
- 無障礙：每個欄位都有可見標籤；錯誤訊息容器使用 `role="alert"`；載入區使用 `aria-busy="true"`；建議按鈕一律是實際的 `<button type="button">`，可用 Tab 聚焦、Enter 或空白鍵啟動，也可用觸控點選；狀態不只靠顏色，一律同時顯示文字（例如「需審核」標籤、「較早」「較晚」文字）；可點目標至少 44 像素高。
- 提示訊息：操作成功或失敗的頁面提示定位為 `[data-testid="app-toast"]`，失敗提示 `role="alert"`，成功提示 `role="status"`。

## UI-01 同場地空檔建議介面（空檔按鈕、當天已無空檔、點選填回日期與時間、與候補入口並存、與其他規則並列時不顯示）

**路由**：`#/bookings/new`、`#/bookings/:bookingId/edit`、`#/bookings/new?from={預約識別}`（建議區塊出現在這三種表單被拒絕後的錯誤區內，不改變 hash）
**定位**：`[data-testid="alt-suggestions"]` 內的 `[data-testid="alt-slots"]`（預約表單 `[data-testid="booking-form"]`，錯誤區 `[data-testid="booking-form-error"]`）

### 操作

| 操作 | 互動 | 需要內層提供 |
| ---- | ---- | ------------ |
| 看見同場地空檔建議（`alt-slots`、`alt-slot-before`、`alt-slot-after`） | 單次預約、修改預約或再預約一次送出後，若未通過的規則只有「時段被占用」，錯誤區在規則清單與「登記候補」下方顯示標題「同場地最近的空檔」與一行說明，並列出最多兩個按鈕：較早的空檔（`alt-slot-before`）與較晚的空檔（`alt-slot-after`）。按鈕文字為 `HH:mm–HH:mm`，按鈕內另有小字「較早」或「較晚」；日期與所選相同，不重複顯示。某一個方向沒有空檔時，該方向的按鈕不顯示，只顯示另一個方向。前端只照內層給的結果顯示，不自行尋找空檔，也不顯示任何占用者資訊 | 被拒絕的這次送出所對應的同場地空檔建議：同一天、時間長度與所選相同；較早（開始時間早於所選）與較晚（開始時間晚於所選）各最多 1 個，每個含起訖時間點（UTC）；兩個方向都沒有時給出「當天已無空檔」的結果。每個建議都已通過一般單次預約的全部規則，修改預約時已排除該筆預約自己的原時段；內層只在「時段被占用」是唯一未通過的規則時才提供，並且不提供占用者姓名、主題或人數 |
| 看見當天已無空檔（`alt-slots-empty`） | 兩個方向都沒有空檔時，區塊內不顯示任何按鈕，改顯示「當天已無空檔」。不往隔天尋找，使用者可自行改選其他日期，或使用「登記候補」 | 同上（兩個方向都沒有時的結果） |
| 點選空檔建議（`alt-slot-before`、`alt-slot-after`） | 按下按鈕後，表單的日期、開始時間、結束時間改為該建議（以換算後的台北日期與時分填入）；場地、主題與人數維持原樣，再預約模式的唯讀場地也維持不變。錯誤區（規則清單、建議與「登記候補」）隨即收起並清除欄位錯誤，表單上方顯示已填入提示（`alt-applied-notice`，`role="status"`），焦點移到送出按鈕。不會自動送出，也不建立任何預約，修改模式下原預約維持不變。使用者之後手動改動日期、時間或場地任一欄位時，已填入提示隨即移除 | 無（建議資料已隨拒絕結果送達，點選只改表單） |
| 送出由建議帶入的時段（`booking-submit`） | 使用者確認後按「送出預約」或「儲存修改」，與一般送出相同：先做必填與格式檢查，再送出，按鈕立即停用並顯示「送出中…」，欄位停用，連按兩次只送出一次。成功時依模式處理：一般預約顯示結果面板（`booking-result`）；修改預約顯示「預約已更新」結果面板；再預約導向 `#/bookings` 並顯示成功提示。失敗時依最新狀況重新顯示規則清單與重新計算的建議，完整取代舊的建議，不保留過期的按鈕 | 建立單次預約（場地、日期、起訖、主題、人數）或修改預約的結果：成立並回傳狀態（`confirmed`／`pending`，由場地是否需審核決定）；或未通過的規則清單（每項含規則名稱與說明），涵蓋 30 分鐘單位、長度上限、已過去、最遠可預約日、開放時段、人數、時段被占用、持有上限、預約權限暫停；送出時一律重新套用與一般預約相同的規則，建議被點選後才被他人預約時，只會回傳「時段被占用」與依最新狀況計算的建議；修改預約失敗時原預約維持不變 |
| 與其他規則並列時不顯示建議（`booking-form-error`） | 同一次送出除了「時段被占用」還有其他規則未通過（人數、開放時段、日期範圍、長度、持有上限、預約權限暫停等）時，錯誤清單列出全部未通過的規則，包含「時段被占用」，不顯示建議區塊；「登記候補」仍在。使用者修正其他問題後再送出，若只剩占用才會看到建議 | 同「送出由建議帶入的時段」的未通過規則清單（占用與其他規則在同一次回應中並列，建議只在占用為唯一未通過規則時提供） |
| 保留登記候補入口（`booking-waitlist-link`） | 時段被占用時，不論有沒有建議，錯誤清單旁都保留「登記候補」按鈕，位置在規則清單內、建議區塊之上；按下開啟 001 UI-05 的登記候補對話框並帶入目前表單內容 | 無（對話框所需資料見 001 UI-05） |
| 欄位失焦與送出前檢查（`booking-end-error`、`booking-attendees-error`、`booking-date-error`、`booking-start-error`、`booking-subject-error`） | 欄位失焦時前端提示：結束須晚於開始、長度不超過單次時長上限、人數為 1 以上的整數且不超過場地容納人數。送出時前端只攔截必填與格式錯誤（日期、時間未選、結束不晚於開始、主題空白、人數不是正整數）；長度超過上限與人數超過容納人數只在欄位下方提示、不攔截送出，交由內層與「時段被占用」一併並列回報（FR-008） | 單次時長上限規則值；所選場地的容納人數 |

### 狀態

| 狀態 | 呈現 |
| ---- | ---- |
| 成功 | 被拒絕且只有「時段被占用」時，錯誤區依序顯示規則清單（標題「無法送出，以下規則未通過：」）、「登記候補」，再顯示「同場地最近的空檔」區塊：較早與較晚各最多一個按鈕，只有一側有空檔時只顯示該側。點選後區塊收起，表單上方顯示已填入提示，表單欄位已更新但尚未送出。建議出現在一般預約、修改預約與再預約一次三種表單 |
| 載入 | 與撞期結果同一次到達，沒有獨立的載入區塊。送出後等待結果期間，表單 `aria-busy="true"`、欄位停用、按鈕顯示「送出中…」；舊的規則清單、建議與已填入提示在送出當下先移除，不顯示過期內容；結果送達後一次顯示規則與建議 |
| 空狀態 | 兩個方向都沒有空檔時，區塊顯示「當天已無空檔」（`alt-slots-empty`），不顯示按鈕，仍顯示「登記候補」；只有一個方向沒有時不算空狀態，該方向的按鈕不顯示 |
| 錯誤 | 沒有獨立的錯誤區塊，錯誤呈現在 `booking-form-error`。其他規則同時未通過：列出全部未通過的規則，不顯示建議；結果沒有附建議（內層未提供或暫時算不出）：只顯示規則清單與「登記候補」，不顯示建議區塊也不顯示錯誤代碼；網路失敗或逾時：顯示「無法送出預約。請檢查網路連線後再試一次。」，不建立預約，表單內容全部保留，按鈕與欄位恢復可用；點選建議後送出前時段被他人預約：重新顯示規則清單與依最新狀況計算的建議；預約權限暫停中：暫停也算一項規則，與占用並列，不顯示建議 |

## UI-02 其他可用場地建議介面（場地按鈕、需審核標示、無可用場地提示、點選換場地、再預約表單不顯示）

**路由**：`#/bookings/new`、`#/bookings/:bookingId/edit`（建議區塊出現在這兩種表單被拒絕後的錯誤區內，不改變 hash）；`#/bookings/new?from={預約識別}`（再預約）不顯示本區塊
**定位**：`[data-testid="alt-suggestions"]` 內的 `[data-testid="alt-venues"]`（預約表單 `[data-testid="booking-form"]`，錯誤區 `[data-testid="booking-form-error"]`）

### 操作

| 操作 | 互動 | 需要內層提供 |
| ---- | ---- | ------------ |
| 看見其他可用場地（`alt-venues`、`alt-venue-option`、`alt-venue-approval`） | 單次預約或修改預約送出後，若未通過的規則只有「時段被占用」，錯誤區在「同場地最近的空檔」下方顯示標題「同時段其他可用場地」與一行說明，並列出場地按鈕（`alt-venue-option`，`data-id` 為場地識別）。每顆按鈕顯示場地名稱與「可容納 {容納人數} 人」；需審核的場地另顯示「需審核」標籤（`alt-venue-approval`），不需審核的不加標示。順序與數量完全依內層給的結果：不需審核者在前、需審核者在後，各自依場地名稱排序，最多 5 個。清單中有需審核的場地時，區塊底部加一行「標示「需審核」的場地，送出後為待審核並先占用時段。」。不顯示設備、地點比對，也不顯示任何占用者資訊 | 被拒絕的這次送出所對應的其他可用場地（已排除目前場地）：啟用中、所選日期與起訖時間完全落在開放時段內、該時段沒有有效預約、候補保留或維護時段、容納人數不小於預約人數；每個含場地識別、名稱、容納人數、是否需審核；已依「不需審核在前、需審核在後、各自依名稱排序」排好，最多 5 個。內層只在「時段被占用」是唯一未通過的規則時才提供 |
| 看見此時段沒有其他可用場地（`alt-venues-empty`） | 沒有任何符合條件的場地時，區塊內不顯示按鈕，改顯示「此時段沒有其他可用場地」；「同場地最近的空檔」區塊仍照常顯示 | 同上（沒有可用場地時的結果） |
| 點選其他場地（`alt-venue-option`） | 按下按鈕後，表單的場地改為該場地並更新場地資訊（`booking-venue-info`，顯示新場地的容納人數與審核說明）；日期、起訖時間、主題與人數維持原樣。錯誤區隨即收起並清除欄位錯誤，表單上方顯示已填入提示（`alt-applied-notice`，`role="status"`），焦點移到送出按鈕。不會自動送出，也不建立任何預約，修改模式下原預約維持不變 | 無（場地的名稱、容納人數與是否需審核已隨建議送達，點選只改表單） |
| 送出由建議帶入的場地（`booking-submit`） | 使用者確認後按「送出預約」或「儲存修改」，與一般送出相同（必填與格式檢查、送出中、連按只送出一次）。成功時依新場地是否需審核決定狀態：不需審核顯示「預約已成立（已確認）」，需審核顯示「預約申請已送出，等待審核（待審核）」；修改預約顯示「預約已更新，目前狀態：{狀態顯示文案}。」。失敗時依最新狀況重新顯示規則清單與重新計算的建議，完整取代舊的建議 | 同 UI-01「送出由建議帶入的時段」（內層重新套用與一般預約相同的規則，並依所選場地是否需審核判定狀態；失敗時附依最新狀況計算的建議） |
| 再預約表單不顯示其他場地（`booking-venue`、`booking-rebook-general-link`） | 再預約模式的場地固定且唯讀，錯誤區只顯示「同場地最近的空檔」，不顯示「同時段其他可用場地」區塊，包含「此時段沒有其他可用場地」的空狀態文字也不顯示；內層即使提供了其他場地的結果，前端也不渲染。想換場地時沿用「改為一般預約」連結前往一般預約表單 | 無（是否為再預約模式由網址是否帶 `from` 判定，前端自行判斷） |

### 狀態

| 狀態 | 呈現 |
| ---- | ---- |
| 成功 | 被拒絕且只有「時段被占用」時，在「同場地最近的空檔」下方顯示「同時段其他可用場地」，列出 1 至 5 顆場地按鈕；需審核者帶「需審核」標籤並排在後面。點選後區塊收起，表單的場地已更新但尚未送出。再預約模式不顯示本區塊 |
| 載入 | 與撞期結果同一次到達，沒有獨立的載入區塊。送出後等待結果期間，表單 `aria-busy="true"`、欄位停用、按鈕顯示「送出中…」；舊的場地建議在送出當下先移除，結果送達後一次顯示 |
| 空狀態 | 沒有任何符合條件的場地時顯示「此時段沒有其他可用場地」（`alt-venues-empty`），不顯示按鈕；同場地空檔建議不受影響。再預約模式不顯示本區塊，也不顯示此文字 |
| 錯誤 | 沒有獨立的錯誤區塊，錯誤呈現在 `booking-form-error`。其他規則同時未通過：列出全部未通過的規則，不顯示場地建議；結果沒有附建議：只顯示規則清單與「登記候補」，不顯示建議區塊；網路失敗或逾時：顯示「無法送出預約。請檢查網路連線後再試一次。」，表單內容全部保留；點選場地後送出前該場地該時段被他人預約：重新顯示規則清單與依最新狀況計算的建議；預約權限暫停中：暫停與占用並列，不顯示建議 |
