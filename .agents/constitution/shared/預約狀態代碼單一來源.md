# 共通條款：預約狀態代碼單一來源

## C-SH-01 -- 預約狀態代碼一律英文 snake_case，三份產出物逐字相同

**強度：MUST**
**作用位置**：

- `contracts/openapi.yaml › components.schemas.*.properties` 中預約與週期性預約批次狀態屬性的 `enum`
- `data-model.dbml › Table.*` 的預約與週期性預約批次狀態欄位，以及 `Project Note` 內的狀態 CHECK 清單
- `contracts/ui-contract.md › ## 共用約定` 與各介面 `### 操作` 中以代碼指稱狀態之處

預約（`bookings.status`）與週期性預約批次（`booking_series.status`）的狀態代碼必須是英文小寫 snake_case（符合 `^[a-z]+(_[a-z]+)*$`）。同一個狀態在三份產出物中的代碼必須逐字相同：openapi 的 `enum` 值、dbml 的 CHECK 清單與欄位預設值、ui-contract 中依狀態決定畫面行為時所指稱的代碼。新增或更名一個狀態代碼時，三份產出物必須同時更新，不得由任何一份自行定出另一份沒有的代碼。中文狀態名稱只作為顯示文案，對應關係只定義在 `shared/src/copy.js` 與 ui-contract.md 的文案表；`enum`、CHECK 清單與欄位預設值不得寫中文。

### Good Example

這個範例的同一組代碼在三份產出物與文案檔中逐字相同，後端、資料庫與前端不需要另外對照。

```text
openapi.yaml        components.schemas.BookingStatus.enum: [pending, confirmed, checked_in, completed, rejected, cancelled, no_show]
data-model.dbml     bookings.status 的 CHECK 清單：pending、confirmed、checked_in、completed、rejected、cancelled、no_show
ui-contract.md      UI-04 依 status = checked_in 隱藏「報到」按鈕
shared/src/copy.js  checked_in → 已報到
```

### Bad Example

這個範例的 openapi 沒有定義批次「已核准」的代碼，資料庫卻自行定為 `approved`，後端實作時要自己猜兩邊的對應，前端也無從得知該顯示哪個代碼。

```text
openapi.yaml        components.schemas.SeriesInfo.status 只列：pending、confirmed
data-model.dbml     booking_series.status 的 CHECK 清單：pending、confirmed、approved、rejected、cancelled
```
