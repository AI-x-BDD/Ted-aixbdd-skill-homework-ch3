# 前置檢查規範

## Rule 1 -- 只有產物缺漏才停止分析

**強度：MUST**

只有 collect_artifacts.py 輸出的 `missing` 不為空（必要產物、Planner 或介面文檔缺漏）時才停止分析並詢問使用者。check_plan.py 或 check_tasks.py 回報問題時不得停止，必須繼續分析，並把回報的問題列為發現事項。

### Good Example

這個範例在產物齊全、只有 check_tasks.py 回報問題時繼續分析，把腳本回報的問題帶入發現事項。

```text
collect_artifacts.py：missing 為空
check_tasks.py：1 個問題（T046 錨點片段「responses 409」不存在於 contracts/openapi.yaml）
→ 繼續建立追溯模型，T046 的錨點問題列入發現事項。
```

### Bad Example

這個範例因為 check_tasks.py 回報一個錨點問題就停止分析，使用者只拿到一個問題，其他跨產物的覆蓋缺口與不一致都沒有被找出，修完再跑才又發現下一批。

```text
check_tasks.py：1 個問題（T046 錨點片段「responses 409」不存在於 contracts/openapi.yaml）
→ 停止分析，請先修正 tasks.md 後再執行 /analyze。
```

## Rule 2 -- 缺漏必須對應上游 skill

**強度：MUST**

列出缺漏時，每項缺漏必須寫出產出它的上游 skill，並只建議先執行最上游的那一個：spec.md 對應 specify；research.md、techstack.md 對應 technical-research；plan.md、缺少的 Planner 與介面文檔對應 system-analysis；tasks.md 對應 task。

### Good Example

這個範例為每項缺漏寫出上游 skill，並只建議先執行最上游的 technical-research。

```text
002-online-1a2b-chat 缺少以下產物，無法分析：
- research.md、techstack.md（technical-research）
- plan.md 與各端點介面文檔（system-analysis）
- tasks.md（task）

請先執行 /technical-research，再依序產出後續產物。
```

### Bad Example

這個範例只列出缺漏檔名，並建議直接執行 /task，使用者照做後 task 會因缺少 plan.md 與介面文檔而再次停下。

```text
缺少 research.md、techstack.md、plan.md、tasks.md，請先執行 /task。
```
