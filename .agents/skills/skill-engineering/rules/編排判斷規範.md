# 編排判斷規範

## Rule 1 -- 依 Step 特徵選擇 deriver

**強度：MUST**

逐一檢查目標 SOP 的每個 Step，依下表選擇 deriver。一個 Step 可同時符合多項；都不符合的 Step 不交給任何 deriver。

| Step 特徵                               | deriver               |
| --------------------------------------- | --------------------- |
| 含有相同輸入必定得到相同輸出的機械動作  | skill-derive-script   |
| 含有 agent 容易偏離的判斷標準或專案慣例 | skill-derive-rule     |
| 產出具有固定結構的檔案或內容            | skill-derive-template |

### Good Example

這個範例依特徵為每個 Step 選擇 deriver，單純讀取的 Step 不交給任何 deriver。

```markdown
Phase 1 Step 1 READ 讀取目標 skill 的 SKILL.md 與指定 Step → 無
Phase 1 Step 2 THINK 界定指定 Step 中有固定結構的產出 → skill-derive-rule（範圍判斷易偏離）
Phase 3 Step 2 WRITE 回報已抽取的樣板與未執行的建議 → skill-derive-template（固定結構）與 skill-derive-rule（建議的列出條件）
```

### Bad Example

這個範例把每個 Step 都交給 skill-derive-rule，單純讀取的 Step 也被展開，固定結構的產出卻沒有抽樣板，部件數量增加但格式仍靠文字描述約束。

```markdown
Phase 1 Step 1 READ 讀取目標 skill 的 SKILL.md 與指定 Step → skill-derive-rule
Phase 1 Step 2 THINK 界定指定 Step 中有固定結構的產出 → skill-derive-rule
Phase 3 Step 2 WRITE 回報已抽取的樣板與未執行的建議 → skill-derive-rule
```

## Rule 2 -- deriver 依 script、rule、template 順序執行

**強度：MUST**

同一個 Step 需要多個 deriver 時，必須依 skill-derive-script、skill-derive-rule、skill-derive-template 的順序執行：先抽出腳本，避免為已交給腳本的動作撰寫規則；最後抽樣板，讓樣板的連動調整清除與樣板重複的規則。

### Good Example

這個範例依規定順序排列同一個 Step 的 deriver。

```markdown
Phase 3 Step 2：

1. skill-derive-rule
2. skill-derive-template
```

### Bad Example

這個範例先抽樣板再展開規則，skill-derive-rule 只檢查 `rules/` 不檢查 `templates/`，會寫出與樣板重複的格式規則，且不再有連動調整清除它們。

```markdown
Phase 3 Step 2：

1. skill-derive-template
2. skill-derive-rule
```

## Rule 3 -- 存留部件的 Step 必須交給對應 deriver

**強度：MUST**

存留判定為保留的既有部件，其對應 Step 必須交給該部件類型的 deriver，由 deriver 的既有部件沿用規則重新掛載，不得手動掛載或略過。

### Good Example

這個範例的 Step 雖然不需要新規則，仍交給 skill-derive-rule，由它沿用並掛載存留的 RuleFile。

```markdown
存留：rules/樣板邊界判斷.md → 對應 Phase 1 Step 2
Phase 1 Step 2 → skill-derive-rule（沿用存留的 RuleFile）
```

### Bad Example

這個範例判定 Step 不需要新規則就不交給 deriver，存留的 RuleFile 沒有被重新掛載，在 Phase 5 被檢查為孤兒檔案。

```markdown
存留：rules/樣板邊界判斷.md → 對應 Phase 1 Step 2
Phase 1 Step 2 → 無（不需要新規則）
```

## Rule 4 -- 編排提案必須逐項列出變更

**強度：MUST**

提交使用者確認的編排提案必須包含目標 SOP、每個 Step 的 deriver 與理由，以及刪除清單中每個部件的刪除理由與引用它的其他 skill 的處理方式；沒有其他 skill 引用時標示「無」。不得只列出新增的部分。

### Good Example

這個範例同時列出 deriver 編排與刪除清單，刪除項目附上跨 skill 引用的處理方式，使用者可以逐項確認。

```markdown
目標 SOP：（略，見上方）

編排：

- Phase 1 Step 2 → skill-derive-rule：沿用存留的樣板邊界判斷
- Phase 3 Step 2 → skill-derive-template：抽取回報有固定結構

刪除：

- rules/樣板邊界判斷.md Rule 4：新 SOP 已無對應 Step；跨 skill 引用：無
- templates/抽取清單.md：抽取清單無固定結構；跨 skill 引用：skill-review-spec Phase 1 Step 2 → 移除該連結
```

### Bad Example

這個範例只列出要衍生的部件，沒有刪除清單，使用者確認後才發現既有部件被刪除，失去在閘門審視的機會。

```markdown
編排：

- Phase 1 Step 2 → skill-derive-rule
- Phase 3 Step 2 → skill-derive-template
```
