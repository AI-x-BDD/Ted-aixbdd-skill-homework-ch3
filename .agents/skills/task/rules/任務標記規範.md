# 任務標記規範

## Rule 1 -- 編號依執行順序全檔連續

**強度：MUST**

任務編號格式為 `T` 加三位數，從 `T001` 起依任務在檔案中出現的順序連續遞增，跨 Phase 不重新起算。插入或刪除任務後必須重新編號，並同步更新任務描述、「相依與執行順序」「並行機會」中所有引用的編號。

### Good Example

這個範例在 US1 新增資料庫端 repository 後，後續任務整批往後遞增，相依引用一併更新。

```markdown
- [ ] T023 [P] [US1] 實作 `backend/src/repositories/settingsRepository.js`：…
- [ ] T024 [P] [US1] 實作 `backend/src/repositories/albumRepository.js`：…
- [ ] T033 [US1] 實作 `backend/src/services/albumService.js` 的 `listAlbums`…（依賴 T023、T024）
```

### Bad Example

這個範例以 `T023a` 插入新任務，並保留舊的相依編號，「並行機會」中的範圍 `T023～T026` 無法判斷是否包含新任務，相依也指向了錯誤的任務。

```markdown
- [ ] T023a [P] [US1] 實作 `backend/src/repositories/settingsRepository.js`：…
- [ ] T023 [P] [US1] 實作 `backend/src/repositories/albumRepository.js`：…
```

## Rule 2 -- [P] 只標在可與同段任務並行的任務

**強度：MUST**

只有同時符合以下兩項的任務才能標 `[P]`：修改的檔案與同一節其他 `[P]` 任務都不同，且不依賴同一節中尚未完成的任務。修改同一檔案或有「（依賴 …）」指向同一節任務的任務不得標 `[P]`。

### Good Example

這個範例的兩個 repository 檔案不同、互不依賴，標 `[P]`；依賴兩者的服務不標。

```markdown
- [ ] T025 [P] [US1] 實作 `backend/src/repositories/albumRepository.js`：…
- [ ] T026 [P] [US1] 實作 `backend/src/repositories/photoRepository.js`：…
- [ ] T037 [US1] 實作 `backend/src/services/importService.js`：…（依賴 T024～T026、T028、T035、T036）
```

### Bad Example

這個範例把修改同一個 `fileStore.js` 的兩個任務都標 `[P]`，並行執行時兩邊的修改互相覆蓋。

```markdown
- [ ] T028 [P] [US1] 實作 `backend/src/services/fileStore.js`：…
- [ ] T029 [P] [US1] 在 `backend/src/services/fileStore.js` 實作 `startupCleanup(pool)`…
```

## Rule 3 -- [Story] 只標在使用者故事 Phase

**強度：MUST**

使用者故事 Phase 內的每個任務都必須標 `[US<編號>]`，編號與所在 Phase 的故事編號相同；Setup、Foundational 與 Polish Phase 的任務不得標 `[Story]`。標記順序固定為 `[P]` 在前、`[Story]` 在後。

### Good Example

這個範例的 Setup 任務不標故事，US2 的任務標 `[US2]` 並放在 `[P]` 之後。

```markdown
- [ ] T005 [P] 建立根目錄 `eslint.config.js`…
- [ ] T044 [P] [US2] 在 `backend/src/repositories/albumRepository.js` 新增 `findById(conn, id)`：…
```

### Bad Example

這個範例把共用的 Foundational 任務標為 `[US1]`，又把標記順序顛倒，追溯時會誤以為該任務只屬於 US1。

```markdown
- [ ] T013 [US1] 實作 `backend/src/db/pool.js`…
- [ ] T044 [US2] [P] 在 `backend/src/repositories/albumRepository.js` 新增 `findById(conn, id)`：…
```

## Rule 4 -- 相依寫在描述末尾且只指向先前任務

**強度：MUST**

任務依賴其他任務時，在描述末尾以「（依賴 T0xx、T0yy）」標示，連續範圍寫成 `T0xx～T0yy`。只能依賴編號比自己小的任務；需要依賴後面的任務時，必須調整任務順序。

### Good Example

這個範例的路由依賴前面已排好的服務任務。

```markdown
- [ ] T039 [US1] 實作 `backend/src/routes/photos.js` 的 `POST /api/photos`：…（依賴 T037）
```

### Bad Example

這個範例的頁面任務依賴排在後面的元件，依序執行的 AI 走到 T044 時依賴尚未完成，只能自行先寫元件或跳過。

```markdown
- [ ] T044 [US1] 實作 `frontend/src/pages/homePage.js`：…（依賴 T046）
- [ ] T046 [P] [US1] 實作 `frontend/src/components/albumCard.js`：…
```
