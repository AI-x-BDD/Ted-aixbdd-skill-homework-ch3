# 規格內容撰寫規範

## Rule 1 -- 不得寫入技術實作

**強度：MUST**

規格只描述使用者可觀察的行為與結果，不得指定程式語言、框架、資料庫、API、資料表或檔案結構等實作方式。需要限制實作時，改寫成使用者可觀察的條件。

### Good Example

這個範例以使用者可觀察的結果描述資料保存，不限定保存方式。

```markdown
- **FR-015**：系統**必須**保存使用者自訂的排列順序，重新開啟後維持不變。
```

### Bad Example

這個範例指定了儲存技術與資料表，規格把技術決策提前寫死，後續規劃無法再依需求選擇實作方式。

```markdown
- **FR-015**：系統**必須**將排列順序以 JSON 存入 SQLite 的 album_order 資料表。
```

## Rule 2 -- 驗收情境必須涵蓋非正常路徑

**強度：MUST**

每個使用者故事的驗收情境除了正常路徑，必須至少包含一個非正常路徑，例如錯誤輸入、資料損毀、操作取消、載入中、空狀態或僅用鍵盤操作。

### Good Example

這個範例在正常送出之外，加入必填欄位缺漏的情境。

```markdown
1. **假設** 員工有 5 天特休，**當** 送出 2 天特休申請，**那麼** 申請狀態為「待審核」。
2. **假設** 員工未選擇請假日期，**當** 按下送出，**那麼** 申請不會送出，日期欄位顯示「請選擇請假日期」。
```

### Bad Example

這個範例只有正常路徑，錯誤輸入時系統該怎麼反應沒有被定義，實作者只能自行猜測。

```markdown
1. **假設** 員工有 5 天特休，**當** 送出 2 天特休申請，**那麼** 申請狀態為「待審核」。
2. **假設** 員工有 5 天特休，**當** 送出 1 天特休申請，**那麼** 申請狀態為「待審核」。
```

## Rule 3 -- 需求與成功標準必須可驗證

**強度：MUST**

FR、NFR、SC 必須寫出可判斷是否達成的具體條件；成功標準必須含數值、比例或次數。不得使用「快速」、「友善」、「穩定」等無法驗證的形容詞。

### Good Example

這個範例以數值寫出成功標準，驗收時可直接量測。

```markdown
- **SC-003**：開啟含 200 張照片的相簿時，第一屏縮圖在 1 秒內顯示。
```

### Bad Example

這個範例只寫出形容詞，無法判斷多快才算達成，驗收時各方各有解讀。

```markdown
- **SC-003**：開啟相簿時要快速流暢，帶給使用者良好體驗。
```

## Rule 4 -- 未經釐清的決定必須寫入假設

**強度：MUST**

釐清紀錄沒有涵蓋、由 AI 自行選定預設值的決定，可以寫入需求，但必須同時在「假設」中列出所選的預設值，讓使用者能辨識並推翻。不得讓 AI 自選的預設值只出現在需求中。

### Good Example

這個範例的日期格式未經釐清，寫入需求的同時在假設中標明是預設值。

```markdown
- **FR-006**：相簿名稱**必須**以「YYYY年M月D日（星期X）」格式顯示。

## 假設

- 相簿名稱的日期格式預設為「YYYY年M月D日（星期X）」，含星期、月日不補零。
```

### Bad Example

這個範例把未經釐清的日期格式直接寫成需求，看起來像使用者確認過的決定，使用者審閱時不會發現這是 AI 的推測。

```markdown
- **FR-006**：相簿名稱**必須**以「YYYY年M月D日（星期X）」格式顯示。

## 假設

- 本版本為單一使用者、個人使用的應用程式。
```

## Rule 5 -- 未釐清時必須刪除釐清紀錄

**強度：MUST**

未委派 clarify、沒有任何問答時，必須刪除「## 釐清紀錄」標題與其下所有場次，保留「**輸入**」行。不得保留空標題，也不得寫「無」或虛構問答。

### Good Example

這個範例未經釐清，刪除釐清紀錄標題，「**輸入**」行直接接在狀態之後。

```markdown
**狀態**：草稿

**輸入**：使用者描述：「幫我做一個請假申請功能，員工可以送出特休申請，主管審核後通知員工結果。」

## 使用者情境與測試 _（必填）_
```

### Bad Example

這個範例未經釐清卻保留標題並填入「無」，審閱者會誤以為漏寫了釐清內容，空場次也讓 spec.md 多出沒有資訊的段落。

```markdown
**狀態**：草稿

## 釐清紀錄

### 場次 2026-10-25

- 無

**輸入**：使用者描述：「幫我做一個請假申請功能，員工可以送出特休申請，主管審核後通知員工結果。」

## 使用者情境與測試 _（必填）_
```
