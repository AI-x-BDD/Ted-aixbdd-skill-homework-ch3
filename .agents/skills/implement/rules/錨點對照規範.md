# 錨點對照規範

## Rule 1 -- 需讀原因不得當作內容來源

**強度：MUST**

需讀原因只說明該位置是哪些決定的依據，實作需要的欄位、值、文案與行為必須取自錨點原文。不得只讀需讀原因就推測原文內容，也不得以記憶中的同類規格取代原文。

### Good Example

這個範例依需讀原因知道要找 Set-Cookie 屬性，實際屬性取自 openapi.yaml 原文。

```text
必讀：contracts/openapi.yaml › createSession › responses 200 — Set-Cookie 屬性以此為準
原文：Set-Cookie: sid=...; HttpOnly; SameSite=Lax; Path=/
實作：依原文設定 HttpOnly、SameSite=Lax、Path=/
```

### Bad Example

這個範例只看需讀原因，依慣例加上 `Secure` 與 `Max-Age`，開發環境以 http 存取時瀏覽器不送 cookie，登入後所有請求都回 401。

```text
需讀原因提到 Set-Cookie → 依慣例設定 HttpOnly; Secure; SameSite=Strict; Max-Age=86400
```

## Rule 2 -- 錨點必須定位到原文中的同名位置

**強度：MUST**

錨點依 `›` 逐層定位到檔案中的段落標題、operationId、Table、頂層定義（如 `type Room`、`service RoomService`）、識別碼或 `data-testid`。任一層在原文找不到同名位置時視為錨點找不到，不得改用名稱相近的段落或整份檔案替代。

### Good Example

這個範例在 research.md 找不到 `R-13` 時判定錨點找不到。

```text
錨點：research.md › R-13
research.md 只有 R-01～R-12 → 錨點找不到，停止 T010
```

### Bad Example

這個範例找不到 R-13 就改讀內容相近的 R-12，R-12 談的是部署而非遷移，schema_migrations 的設計只能自行補完。

```text
找不到 R-13，R-12 也提到資料庫 → 以 R-12 為準
```

## Rule 3 -- 任務描述與原文不一致時不得自行擇一

**強度：MUST**

任務描述中的具體值、名稱、狀態碼、路徑或行為，與錨點原文矛盾時，或同一任務的兩個錨點原文彼此矛盾時，視為錨點衝突。任務描述寫了原文未提及的細節不算衝突，依任務描述實作。

### Good Example

這個範例區分衝突與補充：連線數矛盾判定衝突，原文未提的 `namedPlaceholders` 依任務描述實作。

```text
任務：connectionLimit: 10、namedPlaceholders: true
research.md › R-13：連線池上限 5，未提 namedPlaceholders
→ connectionLimit 衝突，停止 T011
```

### Bad Example

這個範例遇到矛盾時選擇「看起來比較新」的錨點原文，任務描述與實作從此不一致，下一個依賴連線池大小的任務又依任務描述的 10 設計。

```text
任務寫 10，R-13 寫 5 → research 比較權威，改用 5 並繼續
```
