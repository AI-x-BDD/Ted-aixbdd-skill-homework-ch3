# 共通條款：時間格式

## C-SH-02 -- 時間點存 UTC、API 回應用帶 Z 的 ISO 8601、使用者輸入用台北當地日期與時分

**強度：MUST**
**作用位置**：

- `contracts/openapi.yaml › components.schemas.*.properties`、`paths.*.*.parameters` 與 `paths.*.*.requestBody` 中的時間屬性與參數
- `data-model.dbml › Table.*` 中表示時間點的欄位
- `contracts/ui-contract.md › ## 共用約定`

時間點在三份產出物中必須一致：

1. API 回應與資料結構中所有時間點屬性必須是 `type: string`、`format: date-time`，值為帶 `Z` 的 ISO 8601 UTC 字串，例如 `2026-11-20T02:00:00.000Z`。
2. 資料表中所有表示時間點的欄位必須是 `datetime(3)`、存 UTC，欄位名以 `_at` 結尾，欄位 note 標明 UTC。不是時間點的欄位（例如以台北當地一天內分鐘數表示的開放時段）不受此限，但 note 必須標明單位與時區基準。
3. 使用者輸入的預約時間（建立、修改、候補、維護時段、報表區間）在請求中必須是台北當地的 `date`（`YYYY-MM-DD`）加 `startTime`、`endTime`（`HH:mm`），不得以帶時區或偏移量的時間戳作為使用者輸入，由伺服器轉為 UTC。
4. ui-contract.md 的「共用約定」必須有一項寫明：畫面上的時間一律以台北時間（UTC+8）顯示、不隨裝置時區改變，且時間輸入只送出台北當地的日期與時分。

### Good Example

這個範例的資料庫、API 回應與使用者輸入各用一種固定的格式，台北 00:30 的預約不會因為裝置時區而被算到前一天。

```text
data-model.dbml  bookings.start_at datetime(3) [not null, note: 'UTC']
openapi.yaml     回應 Booking.startAt: string, format: date-time → 2026-11-19T16:30:00.000Z
openapi.yaml     請求 BookingInput: date = 2026-11-20、startTime = 00:30、endTime = 01:30（台北當地）
ui-contract.md   共用約定 › 時間顯示：一律以台北時間（UTC+8）顯示；時間輸入只送出台北當地的日期與時分
```

### Bad Example

這個範例讓使用者輸入直接帶 `+08:00` 的時間戳，並且資料庫欄位沒有標明時區，瀏覽器的時區設定一旦不同，台北 00:30 的預約就可能落在前一天或後一天。

```text
data-model.dbml  bookings.start_time datetime [not null]
openapi.yaml     請求 BookingInput: startAt = 2026-11-20T00:30:00+08:00
```
