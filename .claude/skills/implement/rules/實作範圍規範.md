# 實作範圍規範

## Rule 1 -- 只修改任務列出的檔案

**強度：MUST**

只能建立或修改任務描述中寫出的檔案；依 [Ignore 檔規範](Ignore檔規範.md) 補 pattern 的 ignore 檔也算在內。描述以短檔名指稱時，依「路徑慣例」與先前任務建立的檔案解析為完整路徑。完成任務必須修改其他檔案時，必須停止並回報需要修改的檔案與原因。

### Good Example

這個範例把 T035 的 `roomPage.js` 解析為 T017 建立的完整路徑，只修改這一個檔案。

```text
T035 擴充 `roomPage.js` → frontend/src/pages/roomPage.js（T017 建立）
修改檔案：frontend/src/pages/roomPage.js
```

### Bad Example

這個範例實作 T035 時順手修改了 `shared/src/copy.js` 新增一句文案，T008 定義的共用文案被改動卻沒有任何任務記錄，後端錯誤訊息與前端不再一致。

```text
修改檔案：frontend/src/pages/roomPage.js、shared/src/copy.js（補一句「秘數已儲存」）
```

## Rule 2 -- 套件只能使用 techstack.md 列出的版本

**強度：MUST**

依賴宣告檔（如 `package.json`、`go.mod`、`pyproject.toml`、`pom.xml`）只能加入 techstack.md 套件安裝清單中對應目錄列出的套件，版本範圍照列。程式碼只能 import 已宣告的套件與執行環境內建模組，不得為了方便加入工具函式庫、polyfill 或型別套件。

### Good Example

這個範例的 backend 只用 techstack.md 列出的 mysql2 與 ws，cookie 解析以內建模組自行處理。

```text
dependencies：mysql2@^3.24.0、ws@^8.22.0
cookie 解析：自行解析 req.headers.cookie
```

### Bad Example

這個範例為解析 cookie 加入 `cookie` 套件，techstack.md 沒有它，與研究決定的零框架後端不一致，也多了一個未經評估的依賴。

```text
dependencies：mysql2@^3.24.0、ws@^8.22.0、cookie@^1.0.0
```

## Rule 3 -- 契約原文必須逐字照用

**強度：MUST**

UI 文案、錯誤句、`data-testid`、API 路徑、JSON 欄位名稱、狀態列舉值與資料表欄位名稱，必須與錨點原文逐字相同，不得改寫、翻譯、改變大小寫或加上標點。

### Good Example

這個範例的按鈕文案與 `data-testid` 與 ui-contract.md 原文完全相同。

```html
<button data-testid="ready-toggle">準備</button>
```

### Bad Example

這個範例把「準備」改成「我準備好了」、`ready-toggle` 改成 `readyButton`，驗收時依契約找不到元素，文案也與對手畫面的狀態說明不一致。

```html
<button data-testid="readyButton">我準備好了</button>
```

## Rule 4 -- 不實作任務以外的功能

**強度：MUST**

只實作任務描述與其錨點要求的行為，不得提前實作後續任務的功能、撰寫測試或加入未要求的錯誤處理分支與設定項。任務要求的行為必須完整實作，不得留下 `TODO` 或空函式後視為完成。

### Good Example

這個範例的 T030 只實作 `leaveRoom` 的 waiting 分支，playing 與 finished 分支留給 T039。

```js
async function leaveRoom(playerId) {
  // waiting 分支依 T030；playing／finished 分支由 T039 實作
}
```

### Bad Example

這個範例在 T030 一併寫完 playing 分支，T039 的必讀錨點（對戰中明示離開只寫 disconnected_at）沒被讀過，實作直接刪除了玩家列，斷線寬限機制失效。

```js
async function leaveRoom(playerId) {
  // waiting、playing、finished 分支一次寫完
}
```

## Rule 5 -- tasks.md 只能改勾選狀態

**強度：MUST**

執行期間對 tasks.md 的修改只能把完成任務的 `- [ ]` 改為 `- [X]`。不得改寫任務描述、必讀、相依或新增刪除任務；任務內容有誤時停止回報，由使用者以 task 修正。

### Good Example

這個範例只改勾選狀態。

```markdown
- [x] T013 [P] 實作 `backend/src/router.js`：…
```

### Bad Example

這個範例發現 T013 描述與實作不同就改寫任務描述，tasks.md 不再反映 task 的拆解結果，使用者無法追溯為什麼行為和規劃不同。

```markdown
- [x] T013 [P] 實作 `backend/src/router.js`：方法加精確路徑比對，另支援 `:id` 路徑參數
```
