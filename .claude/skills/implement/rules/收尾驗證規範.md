# 收尾驗證規範

## Rule 1 -- 依固定項目對照規格與技術計畫

**強度：MUST**

收尾必須逐項對照下表，每項寫出符合或不符合與依據；不得只寫「實作符合規格」的整體結論。

| 項目     | 對照                                                                                                                                                          |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 任務完成 | 範圍內任務在 tasks.md 皆為 `[X]`                                                                                                                              |
| 依賴     | 各 workspace 的依賴宣告檔（如 `package.json`、`go.mod`、`pyproject.toml`、`pom.xml`、`Cargo.toml`）中的依賴、相依類型與版本範圍等於 techstack.md 套件安裝清單 |
| 專案結構 | 實際建立的目錄與檔案位於 plan.md 專案結構與 tasks.md 路徑慣例所列的位置                                                                                       |
| 環境變數 | 程式讀取的環境變數名稱皆列於 plan.md 專案結構與專案的環境變數範本（如 `.env.example`）                                                                        |
| 需求覆蓋 | 範圍內任務必讀引用的 `FR-`、`NFR-` 編號，其任務皆已完成                                                                                                       |
| 檢查狀態 | 最後一次靜態檢查的語法檢查與 lint 皆通過，腳本列入 `unchecked` 的檔案皆已寫入完成報告                                                                         |

### Good Example

這個範例逐項寫出結果與依據，依賴項目指出具體差異。

```text
依賴：不符合，frontend/package.json 多出 devDependencies "eslint"，techstack.md › 套件安裝清單 › frontend 只列 vite
環境變數：符合，config.js 讀取 PORT、DATABASE_URL、ALLOWED_ORIGINS、DISCONNECT_GRACE_MS，皆列於 .env.example
```

### Bad Example

這個範例只寫整體結論，多出的依賴與漏列的環境變數都沒有被發現。

```text
實作符合 spec.md 與 plan.md。
```

## Rule 2 -- 不符合項目只回報不修改

**強度：MUST**

收尾發現的不符合項目必須寫入完成報告，不得在此階段修改程式碼或 tasks.md；修正需要新的任務，由使用者決定是否回到 task 補任務。

### Good Example

這個範例把多出的依賴列入報告，交由使用者決定。

```text
完成報告 › 收尾驗證：依賴不符合，建議以 task 新增任務移除 frontend 的 eslint 依賴
```

### Bad Example

這個範例在收尾時直接刪除依賴，這個修改沒有任務、沒有讀過錨點、也沒有重跑靜態檢查，可能讓 frontend 的 lint 失效。

```text
發現 frontend 多出 eslint → 直接從 frontend/package.json 移除
```
