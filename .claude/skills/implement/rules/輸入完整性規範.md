# 輸入完整性規範

## Rule 1 -- 腳本回報任一缺漏即停止

**強度：MUST**

tasks.md 不存在、腳本回報沒有任何任務、`missing_anchor_files` 不為空或 `unknown_dependencies` 不為空時，必須停止，不得開始任何任務。不得自行補拆任務、改寫錨點或刪除指向缺漏檔案的必讀；缺少 tasks.md 或任務格式不符時請使用者執行 task，缺少 Spec Package 檔案時請使用者執行產出該檔案的上游 skill。

### Good Example

這個範例在缺少 data-model.dbml 時停止，並指出補齊的上游 skill。

```text
無法開始實作：必讀錨點指向的檔案不存在。
- data-model.dbml（T009、T020、T021 等 12 個任務引用）
請先執行 system-analysis 產出資料庫端介面文檔，再重新執行 /implement。
```

### Bad Example

這個範例在缺少 data-model.dbml 時改依 plan.md 推測資料表欄位繼續實作，資料表與介面文檔不一致，後續 repository 任務全部建立在猜測的欄位上。

```text
data-model.dbml 不存在，改依 plan.md 介面盤點推測 rooms、players、guesses 欄位，開始執行 T009。
```

## Rule 2 -- 範圍篩選必須對應到具體任務編號

**強度：MUST**

使用者的範圍篩選必須換算成任務編號清單再執行：指定故事時取該故事 Phase 的所有任務，指定「從 Phase N 開始」時取 Phase N 到最後一個 Phase，指定任務編號時取所列任務；沒有篩選時取所有未完成任務。已勾 `[X]` 的任務不重做。篩選無法對應到唯一的任務集合時，必須詢問使用者。

### Good Example

這個範例把「只做 US1」換算成 Phase 3 的任務編號。

```text
範圍：只做 US1 → Phase 3 的 T020～T027（共 8 個任務）
```

### Bad Example

這個範例把「只做 US1」解讀成「做到 US1 為止」，連同 Setup 與 Foundational 一起執行，超出使用者指定的範圍。

```text
範圍：只做 US1 → T001～T027
```

## Rule 3 -- 範圍外的前置任務未完成時不得自動補做

**強度：MUST**

範圍內任務依賴的任務、或範圍內任務所在 Phase 之前的任務，有任何一個在範圍外且未完成時，必須停止並列出這些任務，由使用者決定是否擴大範圍。不得自動把它們加入範圍執行，也不得略過相依直接執行範圍內任務。

### Good Example

這個範例在 Foundational 未完成時停止，請使用者決定。

```text
無法開始 US1：以下前置任務未完成且不在範圍內。
- Phase 2 Foundational：T007～T019（共 13 個）
請先執行 /implement 完成 Foundational，或指定範圍「從 Phase 2 開始」。
```

### Bad Example

這個範例自動把 Foundational 加入範圍，使用者只預期改動 US1 的檔案，結果連資料庫遷移與共用模組都被建立。

```text
US1 依賴 Foundational，自動一併執行 T007～T019。
```
